LoRA Tuning for Unity NPCs

A deep dive into the practical influence of training parameters, dataset constraints, and best practices for creating specialized GGUF LoRA adapters for LLMUnity games.

1. Demystifying LoRA Parameters

How `Rank (r)`, `Alpha`, and `Dropout` directly control the "brain plasticity" of your NPC during fine-tuning in Unsloth.

Complexity
Rank (r)
8 to 32

What it is: The size of the trainable matrices. Higher rank = more parameters learned.

Practical Influence: Use r: 8 for simple tone/accent changes (e.g., making a pirate speak like a pirate). Use r: 16 to r: 32 if the NPC needs to learn deep lore and entirely new concepts.

Intensity
Alpha (α)
2x Rank

What it is: The scaling factor. Determines how "loud" the new training is compared to the base model's pre-trained knowledge.

Practical Influence: Standard practice is alpha = 2 * r. If your NPC sounds too robotic or hallucinates wildly, lower Alpha to reduce the LoRA's overpowering effect.

Generalization
Dropout
0.0 to 0.1

What it is: Randomly ignores a percentage of neurons during training to prevent memorization.

Practical Influence: Use 0.0 for Unsloth optimized runs on large datasets. If you have a tiny dataset (<50 examples) and the NPC repeats itself exactly, increase to 0.05 or 0.1 to prevent overfitting.

2. Dataset Generation: Specs & Constraints

The quality of the LoRA adapter is entirely dependent on the strictness of the ChatML dataset. Here is how to format NPC Specs effectively.

✖ Bad Example: Loose Constraints

Allows the model to hallucinate or generate overly long, markdown-heavy responses that break Unity UI.

{ "identity": { "personality": "Helpful guide" }, "dialogue": { "conversation_style": "Friendly", "allow_formatting": true }, "system_prompt": "You are a guide. Help the player." }
  • UI Overflow: Generates massive paragraphs.
  • Markdown Leakage: Outputs **bold** or lists that Unity TextMeshPro might struggle with.
  • Hallucination: No specific boundaries defined.

✔ Good Example: Strict Boundaries

Forces the model into a specific character limit, disables markdown, and defines clear failure states.

{ "identity": { "personality": "Patient, clear, and curious", "mannerisms": "Uses timelines and cause/effect" }, "dialogue": { "max_sentences": 5, "max_characters": 500, "allow_formatting": false }, "system_prompt": "## VOICE\nSpeak exactly 3-5 descriptive sentences (~500 characters) | NO markdown formatting, lists, or bullets." }
  • Consistent Length: Fits perfectly in Unity dialogue boxes.
  • Plain Text: Safe for runtime rendering.
  • Predictable: DeepEval quality gates will catch deviations.

3. Unsloth SFT Training Parameters

How batch sizes, epochs, and learning rates affect VRAM usage and model quality in lora-sft-base.yaml.

✖ Bad Example: OOM Crash Risk

Setting parameters too high for a 6GB RTX 3060 will cause immediate CUDA Out Of Memory errors.

training: batch_size: 8 gradient_accumulation_steps: 1 max_seq_length: 4096 num_epochs: 10 learning_rate: 0.002
  • Batch Size 8: Massive VRAM spike.
  • Max Seq 4096: Context window is too large for local hardware.
  • LR 0.002: Too fast, causes catastrophic forgetting (loss spikes).
  • Epochs 10: Severe overfitting on small datasets.

✔ Good Example: The "fast-3b" Preset

Optimized for consumer hardware. Simulates a larger batch size without the VRAM cost.

training: batch_size: 1 gradient_accumulation_steps: 8 max_seq_length: 2048 num_epochs: 3 learning_rate: 0.0002
  • Gradient Acc: Achieves effective batch size of 8 while only using VRAM for 1.
  • Max Seq 2048: Plenty of room for dialogue history.
  • Epochs 3: Gold standard for LoRA instruction tuning.
  • LR 2e-4: Stable convergence for LoRA.

4. Best Practice: LoRA + RAG in Unity

Never fine-tune an NPC to memorize dynamic game state. Use a hybrid architecture.

What LoRA is FOR (The Persona)

  • Speech patterns, accents, and vocabulary (e.g., speaking in Shakespearean English).
  • Deep, static historical lore (e.g., the founding of the Chronos Spire).
  • Formatting enforcement (e.g., never using markdown, staying under 5 sentences).
  • Emotional disposition towards the player.

What RAG is FOR (The Game State)

  • The player's current health, inventory, or equipped items.
  • Dynamic quest progression (e.g., "The goblins attacked the village yesterday").
  • Time of day, weather, or location in the Unity scene.
  • Local Supabase npc_memories injection.

The Ultimate Workflow

1. Unity sends the Player's Prompt.
2. C# script queries local Supabase (RAG) for active quests and nearby items.
3. C# script appends this context to the system prompt.
4. llama-server processes the prompt using the base Llama 3.2 3B model + the NPC's LoRA Adapter.
5. The NPC responds with perfect persona (LoRA) and perfect situational awareness (RAG).
