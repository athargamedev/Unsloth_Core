Canonical stage order

  • 0 preflight/audit
  • 1 validate spec
  • 2 generate -> dataset_raw
  • 3 sanitize -> dataset_clean
  • 4 dataset-eval -> quality_summary
  • 5 train -> adapter_checkpoint
  • 6 export -> gguf_adapter
  • 7 evaluate -> eval_index
  • 8 feedback repair loop

Registry-backed artifacts

  • .pipeline/artifacts.jsonl is append-only
  • Records npc, technique, stage, artifact_type, path, sha256
  • Current stage outputs: dataset_raw, dataset_clean, quality_summary
  • Training/export/eval outputs: adapter_checkpoint, gguf_adapter, eval_index
  • ./ucore audit pipeline-plan reports missing artifacts and next stage

Remaining workflow target

  • One run ID from generation to feedback
  • Dashboard reads registry/DAG state directly
  • Direct scripts keep CLI parity or warn clearly
  • Generate Ollama/legacy paths write the same registry artifacts
  • Hook policy can become fail-closed for production
