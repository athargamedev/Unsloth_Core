Unsloth_Core Workflow

A visual guide to the end-to-end pipeline for generating, sanitizing, gating, and training LLMUnity NPC dialogue adapters using Llama 3.2 3B.

1. The 7-Stage AI Pipeline

Unsloth_Core transforms reference documents into playable Unity NPCs through a strict 7-stage process.

1

Initialization & Spec

Run ucore init <npc_key> to scaffold the NPC. Define the 4-section system prompt in NPC_specs/ and provide domain knowledge in reference_docs/.

2

Generate & Sanitize

Generate dataset grounded in the primer using ucore generate. Then ucore sanitize formats the raw JSONL into strict ChatML format.

3

DeepEval Quality Gate

Before training, ucore dataset-eval tests the dataset locally using the qwen3 Ollama judge. Training is blocked if metrics fail.

4

SFT LoRA Training

ucore train runs Unsloth SFTTrainer over the dataset. The preflight system automatically checks VRAM and adjusts the training preset.

5

GGUF Export

ucore export converts the trained LoRA adapter to a lightweight GGUF format via llama.cpp ({npc}-lora-f16.gguf).

6

Evaluate & Loop

ucore evaluate and ucore feedback analyze the model, finding knowledge gaps to dynamically trigger dataset regeneration.

3. Reference-Grounded Generation

Generating synthetic conversations that accurately represent the defined persona across 5 mandatory interaction categories.

1

Technique Selection

Run generation with --technique docs for grounded facts or template for deterministic baseline output.

2

Category Distribution

Generates exactly 72 examples: identity (8), teaching (32), dialogue (16), quest (8), and refusal (8).

3

JSONL Output

Saves raw conversation arrays to datasets/{npc}/{technique}/train.jsonl, ready for sanitization.

If metrics fail, quality_failures.json is generated and training is blocked. Fix the primer/prompts, not the thresholds.

5. SFT LoRA Training & GGUF Export

Fine-tuning the base Llama 3.2 3B model dynamically utilizing Low-Rank Adaptation for small, efficient weight updates.

1

Hardware Preflight

preflight.py checks nvidia-smi. If VRAM < 10GB, it auto-downgrades from fast-3b to safe-any preset and unloads Ollama.

2

Unsloth Training

Runs SFTTrainer using the train_clean.jsonl dataset. Loss curves and checkpoints are saved to outputs/{npc}/.

3

Adapter Export

convert_lora_to_gguf.py exports an f16 adapter (just a few MBs) to exports/{npc}/{npc}-lora-f16.gguf.

7. Running in LLMUnity

How Unity developers integrate the completed adapter into gameplay.

1

Base Model Runtime

Unity loads the heavy llama-3.2-3b-instruct-q4_k_m.gguf into memory once.

2

Hot-Swappable Adapters

The {npc}-lora-f16.gguf is loaded dynamically based on proximity/interaction. Extremely low VRAM overhead.

3

Local Supabase

Handles npc_profiles, session state, and semantic memory (RAG) directly alongside the game logic.
